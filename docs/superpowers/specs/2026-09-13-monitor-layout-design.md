# Monitor layout plugin — design

Omarchy shell plugin `esemczak.monitor-layout`: a bar widget with a popup panel
that lets the user place an external monitor relative to the laptop panel in
physical terms, and permanently bind workspaces to monitors. Approved 2026-09-13.

## Goals

- Choose which side of the laptop the external monitor sits on and how the two
  are aligned physically, so that cursor crossings between monitors match the
  real desk layout as closely as Hyprland allows.
- Assign each of the ten Omarchy workspaces to the laptop, the external, or
  leave it unassigned, and have that survive reboots and hotplug.
- Remember one layout per external monitor (keyed by its description) and
  re-apply it automatically when that monitor is connected.

## Non-goals

- Drag-and-drop arrangement, three or more monitors, mirroring, rotation.
- Replacing Omarchy's Display panel (brightness, text size).

## Architecture

```
manifest.json            bar-widget plugin, entry Panel.qml
Panel.qml                popup UI; owns a Service instance
Service.qml              state, monitor discovery, apply pipeline
Model.js                 pure functions: layout math, Lua rendering, state (node-testable)
bin/bootstrap-state.sh   prints {state, monitors, requireInstalled} JSON for the shell
bin/safe-write-state.sh  atomically writes state JSON from stdin
bin/apply-layout.sh      writes generated Lua from stdin, reloads Hyprland, reports errors
bin/install-require.sh   adds require("hypr.monitor-layout") to ~/.config/hypr/hyprland.lua
dev-install.sh           copies the repo into ~/.config/omarchy/plugins/<id>/
tests/                   node --test unit tests and a bash test for apply-layout.sh
```

State lives in `~/.local/state/omarchy/settings/monitor-layout.json`.
Generated Hyprland config lives in `~/.config/hypr/monitor-layout.lua`.

### Monitor identity

- Internal panel: first monitor whose name matches `^(eDP|LVDS|DSI)-`.
- External: first enabled monitor that is not internal. Its Hyprland
  `description` string is the profile key, and the generated rules use
  `desc:<description>` so they survive port renames.

### State schema (version 1)

```json
{
  "version": 1,
  "generatedProfile": "<description or empty>",
  "profiles": {
    "<description>": {
      "side": "right",            // left | right | above | below
      "align": "start",           // start | center | end | custom
      "offsetMm": 0,              // custom only: external origin edge minus internal origin edge, mm
      "internalScale": 2,
      "externalScale": 2,
      "workspaces": { "1": "external", "5": "internal" },  // omitted = unassigned
      "persistent": true
    }
  }
}
```

### Layout math (Model.js)

Logical size = pixel size / scale, rounded. The internal panel is the anchor at
0x0. The external's main-axis position follows `side`; its cross-axis offset is
computed in millimetres (`start` = 0, `center` = (internal − external) / 2,
`end` = internal − external, `custom` = offsetMm) and converted to logical
pixels using the internal panel's logical pixels per millimetre. Both positions
are then shifted so the minimum x and y are 0, because Hyprland expects
non-negative positions.

The panel also computes the shared edge overlap in millimetres on both
monitors, shown in the preview as the region where the cursor can cross.
Because the two panels have different pixel densities the alignment is exact
at the anchor point and drifts slightly along the edge; the README says so.

### Generated Lua

```lua
-- Generated by esemczak.monitor-layout. Edits are overwritten on apply.
hl.monitor({ output = "eDP-1", mode = "preferred", position = "0x331", scale = 2 })
hl.monitor({ output = "desc:Apple Computer Inc StudioDisplay 0xB65A586D", mode = "preferred", position = "1440x0", scale = 2 })
hl.workspace_rule({ workspace = "1", monitor = "desc:Apple Computer Inc StudioDisplay 0xB65A586D", persistent = true })
hl.workspace_rule({ workspace = "5", monitor = "eDP-1", persistent = true })
```

Only the active profile is rendered so workspace rules never conflict. Strings
are escaped for Lua. When no profile applies, the file contains only the header.

### Apply pipeline

1. Panel "Apply" → Service renders Lua → pipes it to `apply-layout.sh`.
2. The script writes the file atomically, checks that `hyprland.lua` requires it,
   skips the reload if `omarchy-hyprland-reload-guard paused` says an update is
   in progress, otherwise runs `hyprctl reload` and `hyprctl configerrors`.
3. It prints `{ok, requireInstalled, errors}`; the panel shows the result.
4. On success the Service records `generatedProfile` in state.

Hotplug: the Service listens to Hyprland `monitoradded` / `monitorremoved`
events and refreshes monitor data. If the connected external has a profile and
differs from `generatedProfile`, the Service applies it automatically. When the
file already covers the connected monitor, Hyprland applies the rules itself.

### Install

`install-require.sh` inserts `require("hypr.monitor-layout")` directly after
`require("hypr.monitors")` in `~/.config/hypr/hyprland.lua`, after a timestamped
backup, and is idempotent. The panel offers an "Install" button while the
require is missing; the README documents the manual line.

### UI

- Hero: icon, "Monitor layout", detail of connected monitors.
- Arrangement (external connected): side button group, alignment button group
  with labels adapting to the axis, custom offset number field, per-monitor
  scale dropdowns, and a to-scale preview highlighting the shared edge.
- Workspaces: ten chips that cycle unassigned → external → internal, plus a
  persistent toggle.
- Footer: Apply button, last result, Install button when needed.
- No external: explanatory text and the list of saved profiles.

Keyboard: j/k move between sections, h/l move within a row, Enter activates,
Escape closes. Follows the same PanelKeyCatcher pattern as other panels.

### Error handling

- Missing or corrupt state → defaults, panel still usable.
- `hyprctl` failures or config errors → shown in the footer, state unchanged.
- Oversized script output is discarded (same guard as theme-modes).

### Testing

- `node --test tests/` covers Model.js: identity detection, layout math for all
  sides and alignments, normalisation, overlap, Lua rendering and escaping,
  state parsing and serialisation.
- `tests/apply-layout.test.sh` runs the apply script against a temp HOME with a
  fake `hyprctl` on PATH.
- Manual: `omarchy plugin validate`, dev-install, enable, open the panel.
